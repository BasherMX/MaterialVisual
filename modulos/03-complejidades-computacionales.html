📐 Reglas Fundamentales de Simplificación y Reducción

Al analizar algoritmos reales, rara vez obtenemos un único término puro. Aplicamos estas tres reglas matemáticas para simplificar la expresión a su forma asintótica estándar:

👑 Regla del Término Dominante

Cuando n crece a valores muy grandes, el término de mayor orden (p. ej. n²) eclipsa por completo al de menor orden (n o constantes), por lo que nos quedamos únicamente con el término superior.

O(n² + n + 100) ➜ O(n²)

➕ Regla de la Suma

Si un programa ejecuta una tarea A seguida de una tarea B en secuencia, la complejidad total es la suma de ambas: O(f(n) + g(n)). En este caso: O(n + n) = O(2n).

Paso A: O(n) + Paso B: O(n) ➜ O(2n)

✂️ Eliminación de Constantes

En la notación Big-O nos interesa la tasa de crecimiento cuando n tiende a infinito, por lo que los coeficientes y constantes numéricas se descartan. El factor 2 se elimina, dejando la complejidad final simplemente en: O(n).

O(2n) ó O(500n) ó O(n/2) ➜ O(n)

⚠️ Cuidado con esta trampa común: Entradas Independientes A y B

No podemos asumir que ambas entradas son la misma variable n. Si listaA tiene 10 elementos y listaB tiene 10,000,000 de elementos, sus tamaños son completamente independientes.

Cuando los tamaños de entrada son distintos e independientes (llamémoslos A y B, o n y m), la complejidad formal no se colapsa en una sola letra, sino que se expresa con ambas variables:

O(A + B)

▶️ Bucles Secuenciales: O(A + B)

Como están secuenciales (uno después del otro), la complejidad es O(A + B). Solo podemos usar O(n) si ambas colecciones tienen garantizado el mismo tamaño n.

void ProcesarSecuencial(List<int> listaA, List<int> listaB) { // Bucle 1: corre exactamente A veces foreach (var x in listaA) { Console.WriteLine(x); } // Bucle 2: corre exactamente B veces foreach (var y in listaB) { Console.WriteLine(y); } } // Complejidad Total = O(A + B)

🔄 Bucles Anidados: O(A × B)

Si los bucles fueran anidados (uno dentro de otro), la complejidad sería O(A × B). Por cada elemento de A se recorren todos los de B.

void ProcesarAnidado(List<int> listaA, List<int> listaB) { // Por cada elemento de listaA (A iteraciones)... foreach (var x in listaA) { // ...recorre toda listaB completa (B iteraciones) foreach (var y in listaB) { Console.WriteLine(x + y); } } } // Complejidad Total = O(A × B)

🌲 Caso Recursivo Clásico: C# y Ramificación Exponencial

Analicemos un caso clásico en C#: la función de Fibonacci recursivo sin memorización. Cada llamada engendra dos sub-llamadas, provocando un árbol de llamadas binario de profundidad n con complejidad O(2ⁿ) (Exponencial).

public class RecursionDemo { // Cada invocación se desdobla en 2 llamadas public int Fibonacci(int n) { if (n <= 1) return n; // Caso base O(1) // Dos ramas de recursión: T(n) = T(n-1) + T(n-2) + O(1) return Fibonacci(n - 1) + Fibonacci(n - 2); } } /* * Complejidad de Tiempo: O(2ⁿ) (Exponencial) * Complejidad de Espacio: O(n) (Pila de llamadas de profundidad n) */
