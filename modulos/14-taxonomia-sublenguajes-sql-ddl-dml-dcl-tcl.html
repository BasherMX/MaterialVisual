Bases de Datos Relacionales · ANSI/ISO SQL

Taxonomía de Sublenguajes SQL

Guía integral y laboratorio interactivo de los cuatro sublenguajes fundamentales del estándar SQL: DDL (Definición), DML (Manipulación), DCL (Control) y TCL (Transacciones), más la rama DQL (Consultas).

🌐 Arquitectura Funcional de SQL

SQL (Structured Query Language) no es un monolito aislado; es un lenguaje declarativo orientado a conjuntos dividido en subconjuntos especializados según el nivel de abstracción del motor relacional: el catálogo de esquemas, los datos tabulares, la seguridad y la consistencia transaccional.

DDL · Metadatos

Data Definition Language

Lenguaje de Definición de Datos

Define, altera o destruye las estructuras de almacenamiento físico y lógico (tablas, índices, vistas, esquemas, restricciones) en el diccionario de datos.

COMANDOS CLAVE:
CREATE ALTER DROP TRUNCATE RENAME

⚠️ En la mayoría de motores (Oracle, MySQL), ejecuta autocommit implícito y adquiere bloqueos exclusivos de esquema.

DML / DQL · Tuplas

Data Manipulation Language

Lenguaje de Manipulación & Consulta

Permite operar directamente con las tuplas (filas) de las tablas existentes. Añade, modifica o remueve instancias sin alterar el esquema.

COMANDOS CLAVE:
INSERT UPDATE DELETE MERGE SELECT (DQL)

💡 SELECT a menudo se clasifica como DQL (Data Query Language) por ser de solo lectura y libre de efectos colaterales mutables.

DCL · Seguridad

Data Control Language

Lenguaje de Control de Datos

Gestiona los derechos de acceso, privilegios y roles de usuarios sobre los objetos del catálogo, implementando modelos RBAC y el principio de menor privilegio.

COMANDOS CLAVE:
GRANT REVOKE DENY

🔒 Controla privilegios a nivel de servidor, esquema, tabla o columna (SELECT, INSERT, EXECUTE, ALL PRIVILEGES).

TCL · Atomicidad ACID

Transaction Control Language

Lenguaje de Control de Transacciones

Gobierna los límites de las unidades de trabajo lógicas (LUW). Asegura las garantías ACID (Atomicidad, Consistencia, Aislamiento, Durabilidad).

COMANDOS CLAVE:
COMMIT ROLLBACK SAVEPOINT SET TRANSACTION

🔄 Permite confirmar cambios permanentes en el WAL o revertir modificaciones en caso de error o concurrencia.

⚙️ Pipeline de Ejecución Interna en el RDBMS

Cada sentencia SQL atraviesa módulos especializados del motor relacional según su sublenguaje:

1. Parser & Lexer
Valida sintaxis SQL y genera el Árbol AST
➔
2. Auth & DCL Engine
Verifica si el usuario tiene permiso (GRANT)
➔
3. Planner / Optimizer
Genera el plan físico óptimo para DML/DQL
➔
4. Lock & Transaction (TCL)
Administra aislamiento, bloqueos y WAL log
➔
5. Catalog / Storage (DDL)
Aplica mutaciones a páginas de disco o metadatos

⚔️ El Duelo Canónico: DELETE vs TRUNCATE vs DROP

Una de las distinciones fundamentales más evaluadas en certificaciones y arquitectura de bases de datos. Aunque las tres instrucciones destruyen o eliminan información, pertenecen a sublenguajes distintos y operan de forma radicalmente diferente a nivel de almacenamiento y registro en el Transaction Log.

Criterio Técnico DELETE (DML) TRUNCATE (DDL) DROP (DDL)
Sublenguaje Oficial DML (Manipulación) DDL (Definición rápida) DDL (Definición / Catálogo)
Mecanismo de Borrado Fila por fila recorriendo páginas. Evalúa cláusula WHERE opcional. Deasigna las extensiones y páginas completas de disco (Data Pages deallocation). Elimina la tabla física, sus índices, restricciones y la definición en el diccionario.
Registro en WAL / Log Alto: Registra cada fila borrada individualmente en el WAL. Mínimo: Solo registra la deasignación de páginas (Minimal Logging). Mínimo: Registra la baja del objeto en el catálogo del sistema.
Velocidad / Rendimiento Lento en tablas de gran escala (millones de tuplas). Genera alto I/O. Ultra rápido: Independiente de la cantidad de millones de filas. Ultra rápido: Inmediato.
¿Dispara Triggers? SÍ: Ejecuta triggers BEFORE DELETE y AFTER DELETE por fila. NO: No dispara triggers por fila (no examina tuplas individuales). NO: Los triggers asociados son destruidos.
Reinicio de Autoincrementable NO: Mantiene el valor actual de IDENTITY o secuencia. SÍ: Reinicia el contador de identidad a su valor inicial (Seed). La estructura desaparece por completo.
Espacio Físico en Disco Puede no liberar páginas al sistema operativo de inmediato (queda en free space de la tabla). Libera inmediatamente las páginas de datos asignadas a la tabla. Libera todo el espacio en disco asociado al objeto.
Soporte de ROLLBACK SÍ: Siempre reversible dentro de una transacción activa. Parcial: Reversible en PostgreSQL y SQL Server; no reversible en MySQL/Oracle. Reversible solo en RDBMS con DDL transaccional (ej. PostgreSQL).
Restricciones Foreign Key Permitido siempre que no viole integridad referencial. Prohibido si la tabla es referenciada por una FK activa, incluso si está vacía. Requiere eliminar FKs dependientes o usar CASCADE.

🛡️ Las Propiedades ACID y el Gobierno DCL / TCL

El sublenguaje TCL existe para materializar los axiomas ACID en el almacenamiento persistente, mientras que DCL asegura el cumplimiento estricto de gobernanza y protección de datos (Data Governance & ISO 27001).

A · ATOMICITY

Atomicidad: Todo o Nada

Todas las operaciones de la transacción se ejecutan con éxito o ninguna surte efecto. Si ocurre un fallo a mitad de camino, ROLLBACK regresa el sistema al punto previo.

ROL DE TCL:

COMMIT consolida el bloque; ROLLBACK deshace el lote completo de mutaciones.

C · CONSISTENCY

Consistencia: Estado Válido

La transacción solo puede llevar la base de datos de un estado válido a otro válido, respetando todas las restricciones (Constraints, Foreign Keys, Not Null, Checks).

ROL DE DDL & DML:

DDL define las reglas del modelo y DML es evaluado por el motor antes de escribir en disco.

I · ISOLATION

Aislamiento: Concurrencia Segura

Las transacciones simultáneas se ejecutan sin interferir entre sí. Los niveles de aislamiento definen la visibilidad de datos no confirmados (Lecturas sucias, no repetibles, fantasmas).

ROL DE TCL:

SET TRANSACTION ISOLATION LEVEL [READ COMMITTED | REPEATABLE READ | SERIALIZABLE].

D · DURABILITY

Durabilidad: Persistencia Real

Una vez que una transacción emite COMMIT, sus cambios son permanentes y sobrevivirán a fallos de energía o caídas del servidor mediante el registro WAL en disco.

ROL DEL WAL (Write-Ahead Log):

Las páginas sucias en memoria se reconstruyen con el log en el arranque tras una falla.

📍 Mecánica de Puntos de Guardado: SAVEPOINT y Reversión Parcial

En flujos de negocio complejos (por ejemplo, procesamiento de carritos de compras o pagos con comisiones), no siempre se desea abortar la transacción completa ante un error menor: 

BEGIN TRANSACTION;
  INSERT INTO pedidos (id, cliente, total) VALUES (101, 'Ana', 500); -- Paso 1
  SAVEPOINT sp_pago;                                                  -- Punto de control

  UPDATE cuentas SET saldo = saldo - 500 WHERE id = 12;              -- Paso 2 (Fallo de saldo)
  -- Si falla el débito de cuenta secundaria:
  ROLLBACK TO sp_pago;                                                -- Se revierte Paso 2, pero pedido 101 PERMANECE

  INSERT INTO pedidos_pendientes VALUES (101, 'Pago en OXXO');       -- Ruta alternativa
COMMIT; -- Todo se consolida atómicamente
