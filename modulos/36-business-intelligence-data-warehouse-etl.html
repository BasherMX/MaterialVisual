Duelo Doctrinal: Ralph Kimball vs Bill Inmon (Joyanes Cap. 2)

          

            Las dos filosofías arquitectónicas que definen el diseño corporativo de almacenamiento de información para toma de decisiones:
          


          

            

              
                ENFOQUE BOTTOM-UP (DIMENSIONAL)
              
              
Ralph Kimball

              

                El Data Warehouse se concibe como la unión coherente de todos sus Data Marts departamentales mediante dimensiones conformadas (Conformed Dimensions).
              

              
    
                
  • Modelado: Dimensional puro (Tablas de Hechos y Dimensiones).
    • 
                
  • Normalización: Desnormalizado intencionalmente para optimizar lecturas.
    • 
                
  • Velocidad de entrega: Rápida; permite construir Data Marts funcionales de forma iterativa y modular.
    • 
                
  • Orientación: Diseñado directamente para el usuario de negocio y herramientas de BI (Power BI, Tableau).
    • 
              

            


            

              
                ENFOQUE TOP-DOWN (RELACIONAL)
              
              
Bill Inmon (Padre del Data Warehouse)

              

                Define el Data Warehouse como: "Una colección de datos orientada a temas, integrada, no volátil y variante en el tiempo para el apoyo a decisiones directivas".
              

              
    
                
  • Modelado: Relacional estricto en Tercera Forma Normal (3FN).
    • 
                
  • Estructura: Almacén corporativo central (EDW) único; los Data Marts departamentales se desprenden secundariamente de este EDW.
    • 
                
  • Velocidad de entrega: Lenta al inicio; requiere diseñar el modelo de datos unificado de toda la organización.
    • 
                
  • Consistencia: Máxima fuente única de la verdad (Single Version of Truth).
    • 
              

            

          

        

      


      
      

        

          
Tuberías de Integración de Datos: ETL Clásico vs ELT en la Nube

          

            Evolución tecnológica del procesamiento de datos según Luis Joyanes Aguilar:
          


          

            
            

              
                ETL (Extract - Transform - Load) · Almacenamiento On-Premise Clásico
              
              

                

                  1. Extracción

                  Bases OLTP / Archivos
                

                ➔
                

                  2. Transformación

                  Servidor ETL dedicado (Limpieza, Joins, Conversión)
                

                ➔
                

                  3. Carga

                  Data Warehouse Destino
                

              

              

                El servidor intermedio puede convertirse en un cuello de botella con grandes volúmenes de Big Data.
              

            


            
            

              
                ELT (Extract - Load - Transform) · Cloud Data Warehousing & Lakehouse
              
              

                

                  1. Extracción

                  Fuentes transaccionales
                

                ➔
                

                  2. Carga Rápida

                  Datos crudos ingresan al Almacén / Data Lake
                

                ➔
                

                  3. Transformación In-Situ

                  Computación distribuida masiva en la nube (Spark, BigQuery)
                

              

              

                Aprovecha la escalabilidad elástica y el poder de cómputo paralelo masivo (MPP) de los motores modernos.
