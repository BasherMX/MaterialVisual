Inyección de Dependencias & C# 12

Fundamentos del contenedor de Inversión de Control (IoC) en .NET: Ciclos de vida Transient, Scoped y Singleton, prevención del antipatrón Captive Dependency y modernización con Constructores Primarios.

📦 Los Tres Ciclos de Vida Canónicos en .NET

El contenedor de dependencias de Microsoft (Microsoft.Extensions.DependencyInjection) gestiona la creación, inyección y destrucción (IDisposable / IAsyncDisposable) de servicios según su contrato de registro:

AddTransient<T>()

Transitorio (Transient)

Se crea una nueva instancia cada vez que el servicio es solicitado o inyectado en cualquier componente.

  • Vida útil: Efímera (se destruye al salir de ámbito).
  • Ideal para: Servicios ligeros y sin estado (ej. validadores, algoritmos puros, conversores de moneda).
  • Cuidado: Si implementa IDisposable y es capturado por un contenedor raíz, puede causar acumulación en memoria.
AddScoped<T>()

De Ámbito (Scoped)

Se crea una única instancia por cada ámbito lógico (en ASP.NET Core, equivale exactamente a una petición HTTP completa).

  • Vida útil: Duración de la petición HTTP; se libera al finalizar la respuesta.
  • Ideal para: DbContext de EF Core, repositorios, contexto de usuario autenticado (claims).
  • Garantía: Todas las clases dentro de la misma petición comparten el mismo estado e instancia.
AddSingleton<T>()

Único (Singleton)

Se crea una sola instancia global la primera vez que se solicita y se reutiliza para todas las peticiones subsecuentes.

  • Vida útil: Todo el ciclo de vida del proceso de la aplicación.
  • Ideal para: Cachés en memoria (IMemoryCache), clientes HTTP reutilizables, configuración inmutable.
  • Requisito Crítico: Debe ser Thread-Safe (seguro ante acceso concurrente por múltiples hilos).
Característica Transient Scoped Singleton
Instancias Creadas 1 por cada punto de inyección 1 por cada petición HTTP (Scope) Exactamente 1 para toda la app
Consumo de Memoria Bajo por objeto, pero alta tasa de GC si se crea masivamente Moderado; ligado a peticiones activas simultáneas Fijo y persistente durante toda la ejecución
Seguridad de Hilos (Thread Safety) Aislado por invocación (poco riesgo) Seguro para peticiones síncronas estándar OBLIGATORIO: Múltiples hilos concurrentes lo acceden
Ejemplo Típico en .NET ITokenGenerator, IOrderValidator ApplicationDbContext, IUnitOfWork IMemoryCache, MetricCollector

🚨 ¡ALERTA ARQUITECTÓNICA: Captive Dependency Detectada!

Has inyectado un servicio Scoped (ej. DbContext) dentro de un servicio Singleton. Como el Singleton nunca muere, mantiene "cautiva" la primera instancia del Scoped para siempre, destruyendo el aislamiento entre peticiones y provocando fugas de memoria o excepciones por concurrencia. 

System.InvalidOperationException: Cannot consume scoped service 'IUserDbContext' from singleton 'IEmailBatchProcessor'.
(Detectado en ASP.NET Core con ValidateScopes = true)

⚡ C# 12 Constructores Primarios en Servicios

A partir de C# 12 (.NET 8), las clases y estructuras pueden declarar parámetros de constructor directamente en la definición de la clase, reduciendo dramáticamente el código repetitivo (*boilerplate*) en servicios con inyección de dependencias.

C# 11 (Tradicional · 22 Líneas) Boilerplate Extenso 
public class PedidoService : IPedidoService
{
    private readonly IOrderRepository _repository;
    private readonly IPaymentGateway _paymentGateway;
    private readonly ILogger<PedidoService> _logger;

    public PedidoService(
        IOrderRepository repository,
        IPaymentGateway paymentGateway,
        ILogger<PedidoService> logger)
    {
        _repository = repository 
            ?? throw new ArgumentNullException(nameof(repository));
        _paymentGateway = paymentGateway 
            ?? throw new ArgumentNullException(nameof(paymentGateway));
        _logger = logger 
            ?? throw new ArgumentNullException(nameof(logger));
    }

    public async Task ProcesarAsync(int id)
    {
        _logger.LogInformation("Procesando {Id}", id);
        await _repository.SaveAsync(id);
    }
}
C# 12 (Primary Constructor · 11 Líneas) Conciso & Expresivo 
public class PedidoService(
    IOrderRepository repository,
    IPaymentGateway paymentGateway,
    ILogger<PedidoService> logger) : IPedidoService
{
    public async Task ProcesarAsync(int id)
    {
        // Los parámetros están en el ámbito de toda la clase
        logger.LogInformation("Procesando {Id}", id);
        await repository.SaveAsync(id);
    }
}

🧠 Puntos Clave de Examen & Buenas Prácticas en C# 12:

  1. Captura de Parámetros: Los parámetros del constructor primario NO son campos readonly de forma predeterminada; si un método interno los reasigna, mutan. En servicios de DI, se debe respetar la convención de no mutarlos.
  2. Constructores Adicionales: Si la clase define constructores secundarios, TODOS deben encadenarse explícitamente al constructor primario mediante this(...).
  3. Validación de Nulos: Puedes validar con sintaxis moderna directamente en el cuerpo o propiedades: private readonly IOrderRepository _repo = repository ?? throw new ArgumentNullException(nameof(repository));
