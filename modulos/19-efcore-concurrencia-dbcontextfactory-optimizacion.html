🚀 Native AOT (Ahead-Of-Time) & JSON Source Generators vs JIT

En microservicios modernos y entornos Serverless (AWS Lambda, Azure Container Apps), el tiempo de arranque en frío (*Cold Start*) y el consumo de memoria en reposo son decisivos. Compara cómo Native AOT compila a binario nativo directo y cómo los Source Generators sustituyen a la Reflection.

CLR JIT Tradicional

Just-In-Time (JIT)

Compila código a IL (Intermediate Language). En runtime, el motor JIT compila a código máquina bajo demanda.

  • Cold Start: ~350 - 450 ms
  • Memoria RAM (Working Set): ~85 - 110 MB
  • Reflection: Ilimitada en tiempo de ejecución
.NET 8+ Native AOT

Native AOT + Source Gen

Compila el código C# directamente a código máquina del procesador (x64/ARM64) antes de ejecutarse, eliminando el compilador JIT.

  • Cold Start: ~10 - 25 ms (Instantáneo)
  • Memoria RAM (Working Set): ~15 - 25 MB (-75%)
  • Serialización: Requiere Source Generators (Cero Reflection)

🏛️ Fundamentos Teóricos y Patrones de Arquitectura EF Core

Síntesis doctrinal sobre la gestión de contextos, conexiones a base de datos y optimización de memoria en aplicaciones empresariales:

Patrón Unit of Work

¿Por qué DbContext no es Thread-Safe?

Internamente, `DbContext` encapsula una única conexión ADO.NET física no concurrente, un lector de datos activo (`DbDataReader`) y un diccionario de seguimiento mutable (`ChangeTracker`). Permitir múltiples hilos simultáneos provocaría colisiones de bytes en la conexión socket y corrupción del estado transaccional.

Patrón Context Factory

El Rol de IDbContextFactory

En lugar de compartir un único `DbContext` inyectado por Scoped, `IDbContextFactory` permite a hilos de segundo plano (como `Task.WhenAll`, Blazor Server o BackgroundServices de Hangfire) crear y destruir contextos efímeros e independientes: 

await using var ctx = factory.CreateDbContext();
return await ctx.Clientes.ToListAsync();

📦 El Modelo de Referencia Canónico: Base de Datos Northwind (Mark J. Price)

ESTÁNDAR ARQUITECTURA / MICROSOFT

En la bibliografía oficial de evaluación de .NET (Mark J. Price, "C# and .NET Modern Cross-Platform Development") y en evaluaciones técnicas de arquitectura de software, Northwind es el esquema relacional estándar para modelar consultas, relaciones y optimización de Entity Framework Core:

TABLAS MAESTRAS (1:N)
  • Categories (1) ➔ (N) Products
  • Suppliers (1) ➔ (N) Products
  • Customers (1) ➔ (N) Orders
TABLA DE ROMPIMIENTO M:N

Order Details resuelve la relación muchos a muchos entre Orders y Products con clave primaria compuesta: (OrderId, ProductId).

CONSULTAS DE ALTO RENDIMIENTO

Uso de .Include() con carga ansiosa y .AsNoTracking() para evitar tracking en reportes masivos de ventas. 

public class NorthwindContext : DbContext
{
    public DbSet<Category> Categories { get; set; }
    public DbSet<Product> Products { get; set; }
    public DbSet<Order> Orders { get; set; }
    public DbSet<OrderDetail> OrderDetails { get; set; }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        // Configuración de clave compuesta para la entidad intermedia de Northwind
        modelBuilder.Entity<OrderDetail>()
            .HasKey(od => new { od.OrderId, od.ProductId });
    }
}

// Consulta optimizada sin ChangeTracker en Northwind:
var reporte = await db.Orders
    .AsNoTracking()
    .Include(o => o.OrderDetails)
    .ThenInclude(od => od.Product)
    .Where(o => o.OrderDate >= fechaInicio)
    .ToListAsync();
