05 · Arquitectura DBMS

Arquitectura ANSI/SPARC de Tres Niveles

El modelo fundacional de tres niveles para el aislamiento de programas frente al almacenamiento físico: Niveles Externo, Conceptual e Interno, Transformaciones de Mapeo, Independencia de Datos y la Discrepancia Teórica vs Comercial identificada por Andy Oppel.

🏛️ La Doctrina ANSI/X3/SPARC (1975)

Propuesta por el comité Standards Planning and Requirements Committee (SPARC) de ANSI, esta arquitectura tiene como objetivo primordial separar las aplicaciones cliente del almacenamiento físico de los datos, permitiendo que la base de datos evolucione sin romper el software preexistente.

NIVEL 1 · EXTERNO

Vistas / Esquemas Secundarios

Es la perspectiva individual del usuario final, del analista o de la aplicación de software.

  • Ocultamiento de Complejidad: Solo expone el subconjunto de datos relevante y autorizado para un rol específico.
  • Multiplicidad: Pueden coexistir múltiples esquemas externos sobre una misma base de datos (ej. Vista Contabilidad, Vista RRHH, Vista App Móvil).
  • Seguridad: Bloquea el acceso a columnas confidenciales (ej. ocultar salarios a contratistas).
SQL: CREATE VIEW vista_publica AS SELECT id, nombre FROM empleados;
NIVEL 2 · CONCEPTUAL / LÓGICO

La Visión Comunitaria Global

Describe QUÉ datos se almacenan en toda la organización, libre de ataduras al hardware físico.

  • Representación Unificada: Describe todas las entidades, atributos, relaciones, tipos de datos y restricciones de integridad (PK, FK, CHECK).
  • Único: Solo existe un único esquema conceptual para toda la base de datos empresarial.
  • Independiente del Almacenamiento: No sabe ni le importa si los datos se guardan en discos HDD, SSD, cintas o si usan compresión.
SQL: CREATE TABLE empleados (id INT PK, nombre VARCHAR, salario NUMERIC);
NIVEL 3 · INTERNO / FÍSICO

La Representación Física en Disco

Describe CÓMO se estructuran y ordenan los bits, bytes y bloques en el dispositivo persistente.

  • Bajo Nivel: Tamaño de páginas de disco (8 KB / 16 KB), ordenamiento de registros, estructuras B+ Tree y punteros de página.
  • Estrategias Físicas: Asignación de Tablespaces, compresión columnar, particionamiento de archivos y hashing.
  • Optimización de I/O: Busca maximizar el throughput y minimizar lecturas de disco.
Estructura: Páginas de datos (Data Pages), Extents, Índices Clustered y WAL.

🔄 Los Mapeos o Transformaciones del SGBD

El Sistema Gestor de Bases de Datos (SGBD) es el responsable de traducir las peticiones entre capas mediante dos procesadores de mapeo:

Transformación de Mapeo Traducción que Realiza Propósito de Ingeniería
Mapeo Externo / Lógico Traduce consultas formuladas sobre una vista externa a sentencias sobre las tablas y relaciones del esquema global. Permite cambiar nombres o esquemas lógicos sin quebrar las vistas utilizadas por las aplicaciones cliente.
Mapeo Lógico / Interno Traduce las sentencias lógicas (tuplas y columnas) a ubicaciones de bloques, punteros y lecturas físicas en los archivos de disco. Permite reorganizar el almacenamiento físico (mover a SSD o reindexar) sin alterar el esquema relacional lógico.

🛡️ Las Dos Grandes Independencias de Datos

El beneficio de ingeniería supremo de la arquitectura ANSI/SPARC es la Inmunidad al Cambio: modificar una capa inferior sin tener que reescribir ni recompilar las capas superiores.

INDEPENDENCIA FÍSICA DE DATOS

Inmunidad del Esquema Lógico ante el Hardware

Es la capacidad de modificar el esquema interno sin alterar el esquema conceptual ni los programas clientes.

Acciones que soporta sin romper aplicaciones:
• Mover archivos a discos de estado sólido (SSD NVMe).
• Reorganizar una tabla de Heap a un Árbol B+ Clustered.
• Crear o destruir índices no agrupados.
• Activar compresión de páginas o cambiar el tamaño de bloque.
INDEPENDENCIA LÓGICA DE DATOS

Inmunidad de las Vistas ante Cambios de Esquema

Es la capacidad de modificar el esquema conceptual sin tener que reescribir las vistas externas ni los programas preexistentes.

Acciones que soporta sin romper aplicaciones:
• Agregar nuevas columnas a una tabla (ej. bono_anual).
• Crear nuevas tablas o relaciones en la base de datos.
• Descomponer una tabla en dos respetando las vistas con JOIN.
• Las aplicaciones antiguas que no usan las nuevas columnas no requieren recompilación.

⚡ La Discrepancia Teórica vs Comercial: El Punto Clave de Andy Oppel

En su influyente literatura de diseño de bases de datos relacionales, el autor Andy Oppel subraya una distinción crucial que suele provocar confusiones entre la teoría académica y la práctica profesional:

📖 La Tesis de Oppel: La Fusión de los Niveles Conceptual y Lógico

"Aunque la teoría formal de ANSI/SPARC postula la existencia de un nivel conceptual puro completamente abstracto e independiente de cualquier modelo, en los motores SGBD comerciales del mundo real (Oracle, SQL Server, PostgreSQL, MySQL, DB2) los niveles conceptual y lógico se implementan de forma fusionada en un único esquema lógico relacional gobernado por DDL."
Criterio Comparativo Teoría Formal ANSI/SPARC Realidad Comercial en RDBMS (Oppel)
Separación Conceptual vs Lógico Estricta. El nivel conceptual describe el universo del discurso sin asumir modelo relacional ni de red. Fusionada: El esquema conceptual ES el esquema lógico de tablas, tipos de datos SQL, PKs y FKs.
Mapeos Requeridos Dos mapeos teóricos separados (Externo-Conceptual y Conceptual-Interno). Se reduce a Mapeo Vista-Tabla (Externo/Lógico) y Mapeo Tabla-Disco (Lógico/Interno).
Lenguaje de Implementación Lenguajes abstractos conceptuales independientes. SQL DDL Estándar (CREATE TABLE, ALTER TABLE, CREATE VIEW).
Definición del Esquema Interno Completamente transparente y aislado por el motor. Permite directivas físicas parciales en DDL comercial (ej. TABLESPACE, INDEX CLUSTERED, PARTITION BY).
