Modelo de Madurez de Richardson

Guía interactiva de los 4 escalones concebidos por Leonard Richardson y popularizados por Martin Fowler para calificar el grado de alineación de una API web con los principios REST.

🏛️ Los 4 Niveles de Madurez hacia la "Gloria de REST"

Haz clic en cada nivel para inspeccionar su comportamiento
🔗 Nivel 3

Controles Hipermedia / HATEOAS (Hypermedia As The Engine Of Application State)

El cliente descubre las acciones y transiciones válidas dinámicamente mediante enlaces incrustados (links/rel) en la respuesta.

Autodescubrimiento Desacoplamiento Total HAL / JSON-LD
🚦 Nivel 2

Verbos HTTP y Códigos de Estado Estándar

Uso estricto de la semántica HTTP (GET, POST, PUT, DELETE, PATCH) y códigos de resultado (200, 201, 204, 404, 409). Idempotencia y seguridad.

GET seguro Idempotencia HTTP Statuses
📦 Nivel 1

Recursos Individuales (URIs Dedicadas)

Se abandona el endpoint monolítico en favor de URIs jerárquicas (/cuentas/123, /citas/456), pero todavía se usa solo POST para todo el tráfico.

División de Recursos URIs semánticas Todo sobre POST
🕳️ Nivel 0

The Swamp of POX (El Pantano de POX / Plain Old XML - RPC)

Un único endpoint (ej. /apiService) y un solo verbo (usualmente POST). HTTP se utiliza únicamente como un simple túnel de transporte.

Túnel HTTP SOAP / XML-RPC Acoplamiento Alto
