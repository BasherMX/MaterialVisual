Métodos HTTP y Códigos de Estado

Catálogo interactivo y simulador de semántica HTTP (RFC 9110): métodos estándar, seguridad (Safe), idempotencia, diferencias críticas entre PUT y PATCH, y taxonomía de códigos de estado (2xx, 3xx, 4xx, 5xx).

GET
🛡️ Seguro 🔁 Idempotente

Recupera la representación del recurso. Jamás debe alterar el estado del servidor. Cacheable por defecto.

POST
⚠️ No Seguro ❌ No Idempotente

Crea un nuevo recurso subordinado o procesa una orden. Múltiples ejecuciones crean múltiples registros.

PUT
⚠️ No Seguro 🔁 Idempotente

Reemplaza por completo el recurso existente en la URI destino. Si no existe, puede crearlo.

PATCH
⚠️ No Seguro ⚠️ No garantizado Idempotente

Modificación parcial de un recurso (solo los campos enviados en el payload). Idempotencia depende de la operación.

DELETE
⚠️ No Seguro 🔁 Idempotente

Elimina el recurso identificado. Múltiples llamadas dejan al recurso igualmente inexistente en el servidor.

OPTIONS / HEAD
🛡️ Seguro 🔁 Idempotente

HEAD obtiene headers sin body. OPTIONS consulta las capacidades y métodos permitidos (CORS Preflight).

💡 Reglas Semánticas y Casos de Examen

🚦 Los 5 Grandes Bloques de Respuestas HTTP

El primer dígito del código de tres dígitos define la categoría general del resultado:

🟢 2xx: Respuestas Exitosas (La solicitud fue recibida, entendida y aceptada)
200 OK
Petición exitosa estándar
Usual en GET, PUT, PATCH exitosos. Retorna el payload del recurso.
201 Created
Recurso Creado
Usual tras un POST. DEBE incluir la cabecera Location: /recurso/id.
204 No Content
Éxito sin cuerpo
Típico tras un DELETE o un PUT/PATCH donde no hay datos que devolver.
🔵 3xx: Redirección (Se deben tomar acciones adicionales para completar la solicitud)
301 Moved Permanently
Movido permanentemente
La URI cambió de por vida. El cliente y motores de búsqueda deben actualizar la URL.
304 Not Modified
Caché Vigente
Uso de cabeceras condicionales (ETag, If-None-Match). No envía cuerpo para ahorrar ancho de banda.
🟠 4xx: Errores del Cliente (La solicitud contiene sintaxis errónea o no puede cumplirse)
400 Bad Request
Sintaxis inválida
JSON mal formado, tipos de datos erróneos o validaciones de esquema fallidas.
401 Unauthorized
No Autenticado
Falta token JWT o credenciales válidas. Exige cabecera WWW-Authenticate.
403 Forbidden
Prohibido / Sin Autorización
El usuario SÍ está autenticado, pero NO tiene los permisos o roles requeridos.
404 Not Found
No Encontrado
La URI no apunta a ningún recurso existente en el servidor.
405 Method Not Allowed
Método no permitido
Ejemplo: Intentar un DELETE en una colección que solo acepta GET y POST.
409 Conflict
Conflicto de Estado
Violación de unicidad (email duplicado) o choque de versiones concurrentes.
🔴 5xx: Errores del Servidor (El servidor falló al intentar procesar una solicitud aparentemente válida)
500 Internal Server Error
Fallo interno del servidor
Excepción no controlada, NullPointer, caída de base de datos o bug en el código.
502 Bad Gateway
Puerta de enlace errónea
Un proxy o API Gateway (ej. NGINX) recibió respuesta inválida del backend.
503 Service Unavailable
Servicio No Disponible
Sobrecarga temporal de peticiones o mantenimiento programado. Cabecera Retry-After.
504 Gateway Timeout
Tiempo de espera agotado
El backend tardó más tiempo del permitido en responderle al proxy intermedio.
