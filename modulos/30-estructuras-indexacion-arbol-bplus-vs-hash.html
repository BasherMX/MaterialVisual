⚙️ Mecánica de la Función Hash y Resolución de Colisiones

Una tabla hash o índice hash utiliza una función de dispersión matemática para transformar una clave arbitraria en un número de índice entero acotado dentro de un arreglo de Buckets.

1. Función Módulo

$h(k) = k \pmod M$
Donde $M$ suele elegirse como un número primo lejano de potencias de 2 para minimizar agrupamientos no uniformes.

2. Separate Chaining

Cada bucket es la cabecera de una lista ligada. Si dos claves tienen el mismo hash, se agregan al final de la lista. En el peor caso (todas las claves al mismo bucket), se degrada a $O(N)$.

3. Linear Probing

Si el bucket $h(k)$ está ocupado, sondea la celda contigua $h(k) + 1, h(k) + 2...$ Sufre del fenómeno de Agrupamiento Primario (*Primary Clustering*).

4. Factor de Carga (α)

$\alpha = \frac{N}{M}$ (número de registros entre número de buckets). Si $\alpha > 0.75$, se produce una degradación exponencial de colisiones y se requiere Rehashing ($2M$).

🌲 Anatomía del Árbol B+ y la División de Nodos (*Splits*)

El Árbol B+ es la estructura estándar de índices en motores como PostgreSQL, MySQL (InnoDB), SQL Server y Oracle. A diferencia del Árbol B tradicional inventado por Bayer y McCreight:

  • Nodos Internos de Enrutamiento: Solo guardan claves y punteros a nodos hijos. No guardan registros ni datos de filas, lo que permite un gigantesco factor de ramificación (*Fan-Out* $\approx 500$ claves por página de 8 KB).
  • Nodos Hoja de Datos: Todos los datos de las tuplas residen exclusivamente en el nivel hoja.
  • Secuencia Horizontal Enlazada: Los nodos hoja están interconectados mediante una lista doblemente enlazada (*Next* y *Prev*), permitiendo lecturas secuenciales ultra veloces para rangos sin tener que volver a subir a la raíz.
  • Balanceo Estricto: Todas las hojas residen exactamente a la misma profundidad (*Depth*), garantizando un tiempo determinista de búsqueda $O(\log_M N)$.
